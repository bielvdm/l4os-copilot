O que é

Um módulo próprio, que todo o L4OS consome.

Backend e front próprios. A IA nunca vive dentro do módulo. É um serviço à parte, com banco e chaves próprios.

Um console central controla tudo. Liga e desliga por módulo, escolhe o modelo, gere chaves e mostra o uso.

Plugável pelo Design System. O <Copilot/> aparece em qualquer módulo, sem código no módulo.

// no front de qualquer módulo
import { Copilot } from "@l4-web/ui";

<Copilot module="demandas" />

// fala com /api/copilot
// outro serviço, outro banco
Cruzamento aberto

Qualquer módulo com qualquer outro.

Não é ligação sob medida entre pares. Uma cópia read-only de cada módulo vive num cérebro de dados único (BigQuery), e a IA junta ali — pelas chaves que todo módulo já tem.

Isolado por design

Banco próprio (pg-copilot)

Guarda só conversas, memória, skills e config. Nunca os dados dos módulos. Escopado por empresa e usuário.

Federação aberta

Qualquer módulo cruza com qualquer outro no cérebro, controlado por config + authz — nunca cross-DB.

text-to-SQL blindado

Só SELECT, allow-list de views, escopo injetado no servidor e role só-leitura no IAM.

Os dados, com segurança

Leitura isolada, nativa do GCP.

O Copilot nunca abre conexão na base de produção. O próprio GCP mantém uma cópia só-leitura, e a IA consulta por text-to-SQL em views curadas.

1 · Produção

Cloud SQL de cada módulo. A fonte da verdade, intocada.

2 · Sincronização

Frescor misto: Datastream (CDC) onde precisa tempo-real; batch de hora/dia no resto.

3 · Cópia read-only

BigQuery (ou réplica) com views curadas e escopo por empresa.

4 · Copilot

Pergunta por text-to-SQL, sempre com role só-leitura.

role só-leituraallow-list de viewslimite de linhas e tempovalidação da queryescopo por empresa a IA não escreve, não altera e não sai do escopo

A IA cruza pelas chaves que já existem — user id, empresa/produto (via tenant_map) e data. Uma réplica read-only serve de ponte pra um piloto; o BigQuery é o padrão pro cruzamento aberto entre módulos.

Motor de IA · greenfield

Multi-provedor, o modelo certo por tarefa.

Gateway próprio — não reusa as IAs dos módulos. Uma interface, vários provedores, trocáveis por config.

Provedores. Anthropic + Gemini atrás de LlmProvider; caminho mcp-worker plugável (experimento de custo).

Router por perfil. analytic · creative · fast — o cérebro certo pra cada tarefa, com override por pergunta.

Economia real. prompt caching + RAG/pushdown + batch. MCP é camada de tools, não alavanca de custo.

// uma interface, vários provedores
interface LlmProvider {
  streamCompletion(req, signal)
  complete(req) // jobs
  embed(texts) // RAG
}

// escolha por módulo
provider_path: "direct" | "mcp"
Segurança e controle

Cada um vê só o que pode.

O acesso passa por três camadas — todas no servidor. O front nunca decide.

1 · Tem o módulo

hasModule — a pessoa já pode ver o módulo (claim l4).

2 · Liberação

access_mode: lista de pessoas ou "liberar pra todos".

3 · Permissão fina

No dado: visualizador não vê faturamento; export com limite.

role só-leituraPII fora das viewsescopo por empresa no servidorallow-list de views a IA herda o authz do L4OS — sem exceção
Memória + automação

Fica mais afiada — e trabalha sozinha.

Aprende com o uso

Guarda conversas e feedback e destila correções, preferências e glossário em cop_memory (pgvector) + RAG de regras. Não é re-treino — é memória que cresce.

Análises agendadas (skills)

Prompts recorrentes em cop_schedule (cron configurável) rodam num Cloud Run Job e entregam no L4OS ou no WhatsApp — no horário que você escolher.

Quanto custa

Cabe no orçamento.

Cerca de R$ 50 por pessoa ao mês num time enxuto — e com teto de gasto que você define, então nunca surpreende no fim do mês.

Como chegar lá

Do piloto ao rollout.

F0

Serviço + chat

L4OS Copilot no ar, resposta em streaming (SSE).

F1

Piloto no DS

<Copilot/> num módulo sem IA (Demandas).

F2

Cérebro de dados

BigQuery + pipes (Reporta) + views + tenant_map.

F3

Cruzamento

text-to-SQL blindado, multi-módulo.

F4

Console

On/off, modelo, budget, quem usa, schedules.

F5

Memória + rollout

RAG, skills, uso — e ligar módulo a módulo.

O piloto é de propósito num módulo sem IA: se ele ganha um copiloto só ligando no console, está provado que pluga em qualquer um. F6 (opcional) = rastreio de precisão arte→venda, atrás de flag, quando esse fluxo for priorizado.
